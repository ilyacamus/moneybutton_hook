# Ниша клиента и база знаний ниши

Аргументы: $ARGUMENTS

Как устроена система: база собирается по нишам. Канал клиента нужен только для того, чтобы определить его нишу. Хуки под сценарий оцениваются и пишутся по знаниям этой ниши. Собственная статистика клиента (skip rate) лишь уточняет оценку.

## Шаги

1. **Ниша клиента.**
   - Если передан `@аккаунт`, вызови `niche_detect` с `username`.
   - Если Instagram не подключён, попроси описание профиля и 5–10 последних подписей и вызови `niche_detect` с `bio` и `captions`.
   - Если передано описание ниши словами, вызови `niche_detect` с `captions: ["<описание>"]`.
   - При уверенности «высокая» или «средняя» повтори вызов с `set: true`. При «низкая» покажи 2–3 варианта и спроси клиента.
2. **Что знает база.** Вызови `niche_model` с id ниши.
   - `model` пустой — модели нет: переходи к шагу 3.
   - `quality` равно «нет сигнала» или «слабая» и роликов меньше 1000 — нишу стоит дополнить (шаг 3).
   - Иначе переходи к шагу 5.
3. **Сбор ниши (если подключён vidIQ).**
   - Возьми поисковые запросы ниши из `niche_list` (`queries`) и добавь 3–5 своих формулировок «болей» ниши.
   - Каждый вызов `vidiq_instagram_tiktok_outlier_search` стоит 5 кредитов vidIQ. Перед сбором скажи, сколько запросов планируешь и сколько это кредитов.
   - Вызывай поиск строго по одному, не параллельно: vidIQ отвечает «Too Many Requests».
   - Ответ каждого поиска сохраняется в файл. Передай путь в `import_outliers` с `niche` и `query`.
   - Цель — от 300 роликов и от 50 авторов в нише.
4. **Слепой разбор.** Вызывай `next_reels` с `scope: "niche"`, `niche: <id>`, `limit: 10`.
   - У роликов из vidIQ вместо кадров есть описание первых 3 секунд.
   - Оценивает **отдельный агент**: передай ему только описание, подпись и рубрику `${CLAUDE_PLUGIN_ROOT}/knowledge/rubric.md`, без просмотров и множителей.
   - Результат сохрани через `save_reel_analysis`.
   - Повторяй, пока очередь не пуста. После 300 роликов спроси, продолжать ли.
   - Затем вызови `niche_model` с `rebuild: true`.
5. **Итог для клиента.**

```
🧭 Ниша: <название> (уверенность <…>; совпало: <слова>)
📚 База ниши: <n> роликов, <n_creators> авторов; медиана отрыва <median_x>×
🎯 Модель залёта: качество <quality> (Spearman <cv.spearman>, ДИ <cv.spearman_ci>),
   верхняя пятая прогноза — <top_fifth_median_x>×, нижняя — <bottom_fifth_median_x>×
↑ С большим отрывом связаны: <drivers_up>   ↓ С меньшим: <drivers_down>
👤 Автор против себя (если есть within_creator): <n> роликов, качество <quality>, AUC <cv.auc>;
   у одного автора лучше заходят хуки, где выше: <drivers_up>
```

Дальше: хуки под сценарий — `/hook-master:hook-generate`, оценка хука — `/hook-master:hook-score`. В обоих ответах будет `niche_potential` по этой нише.

## Честность

- `sample: breakouts_only` — в базе ниши только залетевшие ролики из индекса vidIQ. Модель сравнивает хуки *среди залетевших* (насколько большим бывает залёт), а не залетевший против обычного. Чтобы сравнивать с обычными, нужен сбор лент авторов (`hookbot scout`, режим A).
- Качество «слабая» означает, что прогноз ранжирует хуки чуть лучше случайного. Используй его, чтобы выбрать варианты для A/B-теста, но не обещай клиенту просмотры.
- Чужие ролики нельзя публиковать в открытом репозитории. Пакеты ниш (`hookbot niche export`) храни приватно.
