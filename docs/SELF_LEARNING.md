# Как оценщик учится

«Автономный обучающийся робот» здесь — не дообучение нейросети, а замкнутый цикл, который подстраивает оценку под реальную аудиторию автора и сам собирает для этого данные.

```
 оценка хука ──► хук + 9 оценок рубрики сохранены (SQLite)
      │
      ▼
 публикация ──► через 48 ч бот сам просит skip rate ──► результат сохранён
                                                            │
      ┌─────────────────────────────────────────────────────┘
      ▼
 1. калибровка: веса критериев и прогноз удержания пересчитываются
 2. влияние триггеров: какие приёмы поднимают удержание у этой аудитории
 3. примеры: лучшие и худшие хуки автора идут в промпт как ориентир
 4. каждые 5 результатов Claude переписывает плейбук автора
      │
      ▼
 следующая оценка/генерация уже учитывает всё это
```

## 1. Калибровка рубрики

Каждый хук Claude оценивает по 9 критериям (0–10): сила остановки, любопытство, понятность, релевантность, конкретность, эмоция, обещание ценности, синхронность каналов, честность. Стартовые веса — экспертные ([`rubric.json`](../hookbot/core/data/rubric.json)).

Когда у автора накапливается **5+ роликов** с известным удержанием 3 с (100% − skip rate), [`learning.py`](../hookbot/core/learning.py) строит гребневую регрессию «оценки критериев → фактическое удержание»:

- регрессия стягивается не к нулю, а к априорным весам (prior стоит ~8 наблюдений): на малых данных модель ведёт себя как prior, на больших — как данные. Prior — это веса, выученные на корпусе залетевших роликов вашей ниши, если корпус достаточно велик, иначе экспертная рубрика;
- свежие ролики весят больше старых (полураспад 180 дней): аудитория и тренды меняются;
- выученные положительные коэффициенты, смешанные с prior пропорционально объёму данных, становятся **новыми весами** балла 0–100;
- модель даёт **прогноз удержания 3 с** для нового хука и честную точность — среднюю ошибку на кросс-валидации (leave-one-out на малых выборках);
- пока своих данных мало, используется общая модель по авторам, которые включили обмен анонимными данными (`/share`), а без неё — prior.

Итого цепочка: **экспертная рубрика → корпус ниши → ваш аккаунт**. Быстрее всего её заполняет аудит канала (раздел 5): прошлые ролики со skip rate сразу становятся обучающими данными.

Прогноз для хука фиксируется в момент оценки и сравнивается с фактом, когда приходит результат, — бот показывает ошибку прогноза.

## 2. Влияние триггеров

Для каждого психологического триггера считается среднее удержание хуков с ним и без него (lift в п.п.). Это видно в `/stats` и подмешивается в промпты: «у этой аудитории `curiosity_gap` даёт +12 п.п., `question_hook` −9 п.п.».

## 3. Few-shot из собственных хуков

Лучшие и худшие хуки автора с их удержанием попадают в каждый запрос как ориентир стиля и анти-примеры. Сгенерированные варианты, по которым внесли статистику, сначала «вслепую» оцениваются по рубрике (модель не видит их результат), чтобы попасть в обучающую выборку без утечки.

## 4. Плейбук (рефлексия)

Каждые 5 новых результатов (настраивается `REFLECT_EVERY`) Claude получает таблицу всех результатов, калибровку и lift триггеров и формулирует правила «делать больше / делать меньше» с доказательствами в цифрах, а также A/B-тесты. Плейбук сохраняется и подмешивается во все следующие запросы. В плагине то же делает навык `/hook-master:hook-learn`.

## 5. Аудит канала — старт обучения

Не нужно ждать новых публикаций: `/audit` (или `/hook-master:hook-audit`, `hookbot audit`) забирает ваши прошлые Reels со skip rate через Instagram API или из CSV-выгрузки, вслепую разбирает хук каждого по кадрам и находит, что связано с удержанием именно у вашей аудитории (корреляции Спирмена, перестановочный тест, поправка на множественные проверки). Разобранные ролики сразу становятся обучающими данными для калибровки, а выводы аудита подмешиваются во все запросы. Методика — в [METHODOLOGY.md](METHODOLOGY.md#4-аудит-вашего-канала).

## 6. Корпус и робот-разведчик

Разведчик (`SCOUT_ENABLED=1` в боте, `hookbot scout run`) по расписанию:

1. собирает новые Reels отслеживаемых авторов (Instagram Business Discovery) и свои ролики со статистикой;
2. размечает их внутри автора: залетевший ≥ 3× медианы автора, обычный 0,67–1,5×, — только после 72 часов;
3. вслепую разбирает залетевшие вместе с обычными роликами тех же авторов (в пределах дневного бюджета `SCOUT_DAILY_BUDGET`);
4. пересчитывает, что отличает залетевшие, сверяет с литературой и замечает смену трендов по 30-дневным окнам;
5. раз в неделю ищет свежие исследования; администратор одобряет их перед тем, как они попадут в промпт;
6. присылает администратору сводку цикла и предупреждения: приём сменил статус (например, данные пошли против науки), признак стал чаще встречаться у залетевших, эффект сменил знак.

## 7. Целевая аудитория

`/target` (`/hook-master:hook-target`, `hookbot target`) строит профиль аудитории по демографии, комментариям и итогам аудита, находит через веб-поиск авторов с той же аудиторией, проверяет каждого через Instagram API и собирает их ролики под отдельным тегом. Разведчик дальше следит за ними сам. Отчёт `/gap` показывает, что залетает у этой аудитории и чем отличаются ваши хуки; рекомендация появляется, только если ваш собственный аудит ей не противоречит. Эти выводы тоже идут в каждую оценку и генерацию.

## Автономность

- **Бот сам собирает разметку:** через `FOLLOWUP_HOURS` (48 ч) после оценки напоминает внести skip rate; за результат начисляет +1 анализ.
- **Бот сам переобучается:** калибровка пересчитывается при каждом обращении, плейбук — автоматически по накоплению результатов.
- **Бот сам смотрит Reels:** разведчик круглосуточно собирает и разбирает ролики авторов вашей ниши и аудитории, свои ролики со статистикой забирает из Instagram API.
- **Общая модель** растёт вместе с базой пользователей (только opt-in данные).

## Ограничения

- Корреляция ≠ причинность: на удержание влияют ещё тема, время публикации, обложка, аудитория конкретного дня. Модель учитывает только то, что видно в хуке.
- Прогноз становится полезным примерно с 15–20 роликов; на 5–10 он грубый, и бот показывает его точность.
- Оценки рубрики делает модель, а не человек: калибровка исправляет систематические перекосы, но не случайный шум.
- Skip rate своих роликов приходит из Instagram Graph API (метрика `reels_skip_rate`) или из CSV-выгрузки; для чужих роликов он недоступен, поэтому в корпусе цель — просмотры относительно медианы автора, а не удержание.
- Сказанное в первые секунды без распознавания речи (опция `asr`) модель знает только из подписи и текста на экране.
