# Как оценщик учится

«Автономный обучающийся робот» здесь — не дообучение нейросети, а замкнутый цикл, который подстраивает оценку под реальную аудиторию автора и сам собирает для этого данные.

```
 оценка хука ──► хук + 9 оценок рубрики сохранены (SQLite)
      │
      ▼
 публикация ──► через 48 ч бот сам просит skip rate ──► результат сохранён
                                                            │
      ┌─────────────────────────────────────────────────────┘
      ▼
 1. калибровка: веса критериев и прогноз удержания пересчитываются
 2. влияние триггеров: какие приёмы поднимают удержание у этой аудитории
 3. примеры: лучшие и худшие хуки автора идут в промпт как ориентир
 4. каждые 5 результатов Claude переписывает плейбук автора
      │
      ▼
 следующая оценка/генерация уже учитывает всё это
```

## 1. Калибровка рубрики

Каждый хук Claude оценивает по 9 критериям (0–10): сила остановки, любопытство, понятность, релевантность, конкретность, эмоция, обещание ценности, синхронность каналов, честность. Стартовые веса — экспертные ([`rubric.json`](../hookbot/core/data/rubric.json)).

Когда у автора накапливается **5+ роликов** с известным удержанием 3 с (100% − skip rate), [`learning.py`](../hookbot/core/learning.py) строит гребневую регрессию «оценки критериев → фактическое удержание»:

- регрессия стягивается не к нулю, а к экспертным весам (prior стоит ~8 наблюдений): на малых данных модель ведёт себя как рубрика, на больших — как данные;
- выученные положительные коэффициенты, смешанные с prior пропорционально объёму данных, становятся **новыми весами** балла 0–100;
- модель даёт **прогноз удержания 3 с** для нового хука и честную точность — среднюю ошибку на кросс-валидации (leave-one-out на малых выборках);
- пока своих данных мало, используется общая модель по авторам, которые включили обмен анонимными данными (`/share`), а без неё — экспертная рубрика.

Прогноз для хука фиксируется в момент оценки и сравнивается с фактом, когда приходит результат, — бот показывает ошибку прогноза.

## 2. Влияние триггеров

Для каждого психологического триггера считается среднее удержание хуков с ним и без него (lift в п.п.). Это видно в `/stats` и подмешивается в промпты: «у этой аудитории `curiosity_gap` даёт +12 п.п., `question_hook` −9 п.п.».

## 3. Few-shot из собственных хуков

Лучшие и худшие хуки автора с их удержанием попадают в каждый запрос как ориентир стиля и анти-примеры. Сгенерированные варианты, по которым внесли статистику, сначала «вслепую» оцениваются по рубрике (модель не видит их результат), чтобы попасть в обучающую выборку без утечки.

## 4. Плейбук (рефлексия)

Каждые 5 новых результатов (настраивается `REFLECT_EVERY`) Claude получает таблицу всех результатов, калибровку и lift триггеров и формулирует правила «делать больше / делать меньше» с доказательствами в цифрах, а также A/B-тесты. Плейбук сохраняется и подмешивается во все следующие запросы. В плагине то же делает навык `/hook-master:hook-learn`.

## Автономность

- **Бот сам собирает разметку:** через `FOLLOWUP_HOURS` (48 ч) после оценки напоминает внести skip rate; за результат начисляет +1 анализ.
- **Бот сам переобучается:** калибровка пересчитывается при каждом обращении, плейбук — автоматически по накоплению результатов.
- **Общая модель** растёт вместе с базой пользователей (только opt-in данные).

## Ограничения

- Корреляция ≠ причинность: на удержание влияют ещё тема, время публикации, обложка, аудитория конкретного дня. Модель учитывает только то, что видно в хуке.
- Прогноз становится полезным примерно с 15–20 роликов; на 5–10 он грубый, и бот показывает его точность.
- Оценки рубрики делает модель, а не человек: калибровка исправляет систематические перекосы, но не случайный шум.
- Skip rate вносится вручную: Graph API Instagram, насколько нам известно, его не отдаёт. Если появится — достаточно добавить импорт в `MemoryStore.add_result`.
